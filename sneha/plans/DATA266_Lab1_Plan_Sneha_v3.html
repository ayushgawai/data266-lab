Revision v2, 24 Sep 2026: what changed from the 9 Sep version

Fixed (items 1, 2, 3 and 6 checked by running the spec in PyTorch 2.4.1):

  1. PatchGAN strides. With stride 2 on every layer the output is 15 x 15 with a 94 x 94 receptive field, not the 30 x 30 / 70 x 70 claimed. C512 is now stride 1, which gives the stated numbers. Ayush's plan has the same text.
  2. U-Net innermost norm. InstanceNorm2d on the 512 x 1 x 1 bottleneck raises ValueError: Expected more than 1 spatial element. The innermost and outermost downconvs now have no norm, as in the official unet_256.
  3. Task 1 epoch vs warmup. At 100K characters, batch 64 and context 128, one non-overlapping pass is 13 steps, so 30 epochs is 390 steps, which is less than the 400-step warmup. "Epoch" is now defined explicitly, and warmup is checked against the total step count.
  4. Weight decay. The prose excluded embeddings, but the build spec said "2D parameters only", which includes embeddings. Both now say the same thing.
  5. Identity loss weight. The YAML said lambda_identity: 0.5 while the loss used 5.0. It is now lambda_identity_ratio: 0.5, with the effective weight derived in one place.
  6. CharCNN alphabet. The string has 69 characters but only 68 unique (- appears twice), against a hardcoded Conv1d(70, ...). It is now deduplicated, newline added, 69 channels derived and asserted.
  7. Generation beyond context. 500 generated characters overflow a 128-entry position table. The context is now cropped to the last 128 characters at each step.
  8. Task 1 "defense" wording. The old text called the model "the decoder exactly as printed in Attention Is All You Need". It is decoder-only with learned positions, which is GPT-1's layout; the 2017 decoder has cross-attention and sinusoidal positions. The note now says so.
  9. Which 300 photos for B2A. This was unspecified. There is now a shared held-out list of 300 photos, disjoint from the training subset, used for inference and as the real-photo reference.

Added: the brief's AI-assistant rule as hard constraint 7; a config snapshot in each task folder, per the brief's checklist; large-file handling for GitHub's 100 MB limit (each U-Net generator is 54.4M parameters, about 218 MB); fixed definitions for the slices, ECE, near-threshold fallback and <|endoftext|>; blinded human audit with quadratic-weighted kappa; unit-test conditions; the Task 3 epoch length; and two new sanity gates.

The logging contract

Every training entry point does the following, in this order, before it touches a model:

  1. Resolve the repo root by walking up from the script until it finds requirements.txt. Never use an absolute path.
  2. Load the config, hash it with SHA256, and print the hash as the first line of the log.
  3. Open reproducibility/raw_logs/sneha/<task>_<model>_<UTC timestamp>.log in append mode. If the file exists, abort rather than overwrite.
  4. Log the git commit SHA, the resolved device, the full config, and pip freeze output.
  5. Seed random, numpy, torch, and torch.cuda from config.seed, and set torch.backends.cudnn.deterministic = True.
  6. From then on, log one line per N steps with step, epoch, loss, learning rate, gradient norm, elapsed seconds, and peak memory. Never rewrite the file afterwards.

Manifest, one per task

At the end of every run, write reproducibility/manifests/sneha_task<n>.json containing: config hash, git SHA, seed, python and library versions, GPU name from torch.cuda.get_device_name(), wall clock duration, the checkpoint filename, its SHA256 and storage location (repo path, LFS, or external link), and a metric_rows field that maps each checkpoint to the exact rows it produced in your metrics CSV. That mapping is what makes a number traceable at grading time.

The one line defense of this lane

The block is the original Transformer's: post-norm ordering, ReLU feed-forward with 4x expansion, six layers and eight heads, as in Attention Is All You Need, scaled down to d_model 256 for a character-level corpus. The overall model is decoder-only with learned positional embeddings. That is the GPT-1 arrangement (Radford et al. 2018, which also kept post-norm; GPT-2 moved LayerNorm to the input of each sub-block), not the 2017 paper's decoder. That decoder also has encoder-decoder cross-attention and sinusoidal positions. Do not claim it is "exactly as printed in the paper": an examiner who knows the paper will ask where your cross-attention is. The payoff is that every choice traces to a published model, and your warmup and schedule are load-bearing parts of the post-norm recipe that you can explain, not arbitrary defaults.

Why the innermost block has no norm

InstanceNorm normalises each channel over its spatial positions. At 512 x 1 x 1 there is exactly one position per channel, and PyTorch 2.4.1 refuses: ValueError: Expected more than 1 spatial element when training. With track_running_stats=False this also fails in eval mode. Even where it did not raise, a single element normalises to zero, so the bottleneck would carry no information about the input. The official UnetSkipConnectionBlock therefore leaves the norm off the innermost downconv, and off the outermost downconv too (Encoder 1 above). The innermost up-conv output is 2 x 2 and keeps its norm.

[YOUR CALL] decoder dropout

Dropout 0.5 in decoder blocks 1 to 3 is the pix2pix default, where it supplies the stochasticity a conditional GAN needs. QuestionWhat a good answer contains
