How to use this document

Read once, then work top to bottom.

This document is the complete build specification for Ayush's half of DATA 266 Lab 1. It is written so that a coding agent can execute it end to end without asking a follow up question: every path, every hyperparameter, every metric formula, and every output file is stated explicitly.

Order of operations

Read section 1 and section 3 once. Those two sections constrain everything else.

Run the repo bootstrap prompt below. It creates your folder tree and the config file.

Work tasks in the order 1, 2, 3. Task 3 needs the most GPU time, so its data download and code should be ready before your first lab slot.

After each task, run its acceptance check. Do not move on until it passes.

LayerNorm sits before each sublayer, and the residual path runs unnormalised from input to output. This is the GPT-2 arrangement and it is why the model trains stably without a long warmup.

Blocks

4 identical blocks, Pre-norm

LayerNorm is applied to the input of each sublayer rather than to its output, so the residual stream stays a clean identity path. Xiong et al. 2020 showed this removes the need for a long warmup and keeps gradients well scaled at initialisation.

Attention

4 heads, head dim 64, scaled dot product written by hand

Scores are 
Q @ K.transpose(-2,-1) / sqrt(head_dim)

@ V

Registered buffer 
torch.tril(torch.ones(T, T))

-inf

Brief 1.2.2. Sliced to the current sequence length so shorter batches still work.

Feed forward

Linear 256 to 1024, GELU, Linear back to 256, dropout

Expansion factor 4, as in the original paper. GELU chosen to pair with pre-norm.

Output head

LayerNorm, then Linear 256 to vocab

Brief 1.2.4

Weight tying

input embedding tied to the output head

Saves roughly one vocabulary-by-d_model matrix and is standard in GPT-2. Say in results.md how many parameters it saved you.

The one line defense of this lane

This is the reference GPT-2 decoder. Every component maps to a line in Attention Is All You Need or the GPT-2 paper, which means every design question at the viva has a one sentence answer backed by a citation. Nothing here is exotic, and that is the point: the marks in this task come from a correct implementation, a complete metrics table, and a sharp failure analysis, not from architectural novelty.

Known risk in this lane, and the fix

The main failure mode in this lane is silent, not loud. A causal mask that is off by one still trains and still produces plausible text, but the model is peeking at the next character and your loss will look suspiciously good. Write the mask unit test in the build prompt

Three models that form a ladder: a baseline, then two changes that each test one idea. Every embedding layer is initialised randomly and learned during training.

Model

Configuration

What this model is testing

TextCNN

textcnn

Embedding 128, filters 100 each at widths 3, 4 and 5, ReLU, global max pooling, dropout 0.5, single linear output. Adam 1e-3, batch 64.

Whether local n-gram features alone are enough. Kim 2014. Fast, strong, and the number every later model has to beat.

BiLSTM, max pooled

bilstm

Embedding 128, one bidirectional LSTM layer with hidden 128 per direction, max pooling over time, dropout 0.3. Packed sequences so padding is not fed through the recurrence.

Whether word order and long range context beat bag of n-grams. Max pooling rather than the last hidden state, so a signal anywhere in a long review can survive.

BiLSTM with attention

bilstm_attn

Same recurrent trunk as M2, with additive (Bahdanau style) attention producing a weighted context vector instead of max pooling. Attention scores saved for the error review.

Whether learned weighting beats a hard max. Because M2 and M3 differ in exactly one component, any difference between them is attributable.

Why these three, as a set

A convolutional baseline, then the same task handed to a recurrent model, then attention added on top of that recurrent model. Each step changes exactly one thing, so when a metric moves you can say what moved it. The attention weights in model 3 also give you readable evidence for the twenty error review, which you have to write anyway.

Why this generator, and where it comes from

This is the generator the CycleGAN authors used for 256 x 256 images, and it is the configuration every published Monet result you will find online was produced with. That matters for two reasons: the hyperparameters are known to work without a search you do not have GPU time for, and every choice in the table above has a paper line behind it at the viva. The residual bottleneck operates at 64 x 64 with a large receptive field, which suits a task where the global colour and brush texture change while the scene layout stays put.

Discriminator, both of them

A 70 x 70 PatchGAN, identical for 
D_A
 and 
D_B
, exactly as in the CycleGAN paper: C64 without normalisation, then C128, C256, C512, each being a 4 x 4 stride 2 convolution followed by InstanceNorm and LeakyReLU with slope 0.2, then a final 4 x 4 stride 1 convolution to a single channel. It outputs a 30 x 30 map of real or fake scores rather than one number, which is what makes it a patch discriminator. Do not apply a sigmoid, because the least squares loss expects raw scores.
